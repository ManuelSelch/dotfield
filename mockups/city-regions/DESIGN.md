# City regions — visual review

Revision: 1
Review status: in review
Approval: not yet approved for production implementation.

## Goal

Make touch dispatch forgiving by using the whole surrounding city region as the source/target area. Preserve city circles as the troop launch/arrival boundary. Use the existing understated Dotfield visual language.

## Proposed design

- Generate straight-edged Voronoi cells from seven existing circle positions, clipped to the complete visible board rectangle, including current letterboxed margins.
- Very light green/player, warm red/enemy and neutral region fills; thin muted borders remain between every city, including cities belonging to the same faction.
- Preserve existing circle sizes, counters, faction markers, troop sizes, opening/convergence and border-to-border routes.
- Highlight the full selected source and valid target region; retain circle rings and drag route feedback. No numeric dispatch label.
- Nearest-city selection anywhere inside the board, ownership validation for sources; self-drop and off-board release cancel.
- Portrait viewport lock, rounded board, safe-area spacing. Region geometry regenerates only when board dimensions change.
- Tab/Enter/Space selects source then destination; Escape cancels. Focus-visible polygon border. Reduced-motion preference removes decorative region transitions and lateral troop spreading; essential travel remains visible.

## Review states

- `/city-regions/`: initial map; drag from the large green southern region to any other region, not necessarily the circle. Reset preview restores its initial state.
- `/city-regions/?state=selection`: static source/target highlighting and guide before interaction.
- `/city-regions/?state=expanded`: adjacent player regions, demonstrating shared ownership tint while city borders remain visible.

## Simulated / omitted

- Plain HTML/CSS/JS with SVG and local fake game state, completely separate from production code/dependencies.
- Simplified per-group deductions and arrival combat allow reviewing ownership-tint changes. No growth, enemy AI, per-dot travel collisions, round lifecycle or persistence.
- Temporary all-but-one groups mimic the current game's motion, but are not the authoritative simulator. No promise of native Safari touch/performance correctness.
- Voronoi cells are automatically generated by half-plane clipping for this small mockup; production algorithm/library choice, caching, map validation and boundary ties remain implementation concerns.
- Preview server is loopback-only. A phone/network preview would need separate approval to change binding.
